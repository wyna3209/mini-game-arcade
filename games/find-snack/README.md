# 떡 먹은 용만이 찾기

Phaser 3으로 만든 집중력 게임입니다. 외부 이미지 없이 Graphics로 캐릭터를 그립니다.

별도 버전인 **열매 먹은 눈꼬마 찾기**는 `/games/find-snack/snorunt.html`에서 플레이합니다.
용만이 버전은 `/games/find-snack/`의 HELL MODE이며, 두 버전은 화면 위 링크로 전환할 수 있습니다. 용만이 1단계는 눈꼬마 5단계 다음의 난도에서 시작합니다. 눈꼬마의 1~5단계는 그대로 유지됩니다.
눈꼬마 버전도 5스테이지·각 스테이지 무한 재도전 규칙과 기존 방해요소를 사용하고 최고 점수는 따로 저장합니다.

눈꼬마와 오랭열매 PNG는 [PokéAPI Sprites](https://github.com/PokeAPI/sprites)를 jsDelivr CDN으로 불러옵니다.
주소·투명 여백을 제외한 프레임 범위는 `src/pokemon-assets.js`에 있습니다. 이미지 로드 실패 시 재시도 안내가 표시됩니다.
`npm run build`는 두 버전의 HTML을 모두 `dist`에 생성합니다.

## 실행

```sh
npm install
npm run dev
```

터미널에 표시되는 로컬 주소를 브라우저에서 여세요.

`npm run build`로 배포용 `dist` 폴더를 만들고, `npm run preview`로 확인할 수 있습니다.

## 게임 방법

시작 → 떡 먹은 친구 기억 → 자리 섞기 → 친구 선택 순서입니다.
마우스, 터치 또는 숫자 키 1~3으로 선택하고 Space로 시작하거나 다음 스테이지에 진입합니다.
총 5스테이지이며 맞히면 스테이지 × 100점을 받습니다. 5스테이지 정답 시 축하 메시지와 색종이 효과가 표시됩니다.
실패하면 횟수 제한 없이 같은 스테이지를 다시 도전할 수 있습니다. 정답을 맞히면 다음 스테이지로 진행합니다.
최고 점수는 브라우저에 저장됩니다.

## 수정 위치

- `src/main.js`: Phaser Scene, 캐릭터, 라운드 상태, 이동 애니메이션
- `src/style.css`: 페이지 레이아웃
- `index.html`: 제목과 안내 문구

`src/difficulty.js`에서 난이도 곡선과 방해요소 해금 구간을 조절합니다.

## 난이도와 방해요소

| 스테이지 | 이동 시간 / 기본 섞기 횟수 | 추가되는 요소 |
| --- | --- | --- |
| 1 | 220ms / 24회 | 기존 방해요소 전부 + 3인 동시 이동 |
| 2 | 200ms / 28회 | 다른 자리로 향하는 반투명 분신 |
| 3 | 180ms / 32회 | 교환을 실제로 되돌리는 역재생 |
| 4 | 165ms / 36회 | 이동 도중 되돌아갔다 다시 가는 경로 반전 |
| 5 | 150ms / 40회 | 모든 트릭을 더 높은 빈도로 조합 |

구름은 2초, 새는 2.1초, 개는 2.2초 동안 등장하며 그동안 섞기는 계속 진행됩니다.
회전 섞기는 한 바퀴 + 120도를 돌며, 몸의 360도 회전은 눈꼬마에서 최소 600ms, 용만이 헬에서 최소 430ms 동안 이동합니다.

각 방해요소는 해금 이후 매 스테이지 최소 한 번 등장합니다. 회전은 일반 교환·가짜 이동·연속 섞기를 대신하고, 구름과는 겹칠 수 있습니다.
용만이 HELL MODE는 1스테이지부터 구름·새·개 방해물이 합계 다섯 번 등장합니다. 눈꼬마 버전은 기존대로 3스테이지부터 세 종류가 한 번씩 등장합니다. 새는 좌우 방향이 바뀌고 개는 세 자리 중 무작위 위치에서 올라옵니다.
3인 동시 이동은 서로 다른 높이의 경로로 진행하며, 분신은 반투명으로 표시되고 정답 판정에 참여하지 않습니다. 되감기는 실제 교환을 한 번 취소하므로 최종 위치가 원래대로 돌아옵니다. 경로 반전은 한 쌍이 전진·후퇴·전진한 뒤 정상적으로 자리를 바꿉니다.
360도 회전은 가짜 이동·연속 섞기와 함께 나올 수 있으며, 완료 후에는 똑바로 선 상태로 돌아옵니다.
가짜 이동에서는 자리가 바뀌지 않으며, 모든 이동과 방해물이 끝난 뒤에만 정답을 고를 수 있습니다.
캐릭터 크기와 곡선 이동은 원래 방식이며, 교환하는 두 캐릭터는 같은 속도로 동시에 출발·도착합니다.
연속 섞기는 기본 섞기 횟수에 교환 한 번을 추가하며, 첫 교환이 완료된 뒤 쉬는 간격 없이 시작합니다.
`npm test`로 난이도, 이동 규칙, 재도전과 성공·실패 처리를 검사합니다.

실제 방송의 사진·음원은 포함하지 않은 연습용 구현입니다.
